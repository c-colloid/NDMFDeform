## 0. 要約

**非対応の衣装(別の素体向けに作られた衣装)を、参照した体のメッシュに沿わせて寄せる / 離す**
デフォーマ **Body Fit** を追加する。

- **二重球** = 適用範囲。内側の球の中は 100%、外側の球まで滑らかに減衰する
  (既存の Sphere Mask / Cylindrical 系と同じ操作感・同じハンドル部品)
- **ぴったり / ブカッと** = 体との**隙間の帯 `[minGap, maxGap]`** と全体の効き `factor`。
  帯の幅 0 で「ぴったり」、`pullIn` を切れば「めり込みだけ直してドレープは残す(ブカッと)」
- **パーツ円柱モード(既定)**: 体と衣装のパーツ構造(ヒューマノイドボーン、補助として UV 島 /
  3D 連結成分)を把握し、パーツごとのボーン軸を基準に**放射状**へ動かす(Cylindrical Vertex Transform の
  考え方)。格子 (h, θ) ごとの最内層から放射変位場 Δr を作り、同じ格子の全頂点に同じだけ適用するため、
  装飾は下地との相対オフセットを保って潰れず、腕の装飾は腕の軸基準でしか動かない(胴に吸われない)
- **最近接表面モード(フォールバック)**: 体表面の**最近接点と符号付き距離**(内外判定は角度重み付き
  擬似法線)で目標位置を決め、変位を衣装メッシュの隣接で平滑化してから適用する。骨格がある場合は
  自分のパーツの三角形だけを探す(パーツ制限)。どちらのモードも最後に **minGap を再保証**する
- **メッシュの交差**: 体にめり込んだ頂点は符号付き距離(または半径差)が負になるので、そのまま外側へ
  押し出される。三角形単位の交差・衣装の自己交差は非目標(平滑化と隙間で緩和、文書化)
- **ウェイト**:
  - 適用範囲の重みは二重球で内蔵し、細かい範囲は既存のマスク系デフォーマを後段に重ねる(新規デフォーマ不要)
  - **ボーンウェイトの転写は別機能**とし、本デフォーマは頂点位置のみを扱う(§6.2 に設計メモ)
- **ブレンドシェイプ**: 既定では基本形状で求めた変位をシェイプフレームにもそのまま足す
  (衣装のシェイプ形状を維持、ベイクも軽い)。体側のシェイプ重みは反映する
- **重ね着**: 参照先にも Deform Stack がある場合(体 → 下着 → 服)は参照先を先にベイクする
  依存順序と、プレビューで参照先の変形後メッシュを解決するフックを追加した

## 1. 背景

VRChat では、あるアバター向けに作られた衣装を別のアバターに着せる(非対応衣装)ことが多い。
体型が違うため衣装が体にめり込む / 浮くので、Blender の Shrinkwrap や Lattice で手作業で合わせるのが
現状の主流であり、NDMFDeform の Lattice でも「格子を動かして近づける」作業になる。

要望(原文要約):

> スフィア球を 2 重に用意し、その大きさを近づけたり遠ざけたりすることで、衣装のスキンメッシュを
> 体のメッシュに沿わせて近づけたり遠ざけたりできる Deformer を設計したい。目的は非対応衣装の形を体に
> 合わせること。ぴったりした衣装かブカッとした衣装かを調整したい。想定される問題は、メッシュの交差の
> 処理と、ウェイトの扱い(別 Deformer に役割を分けるか)。

## 2. 前提(v2 パイプライン)

- ベイクコアは各頂点を**頂点ごとのスキン行列(LBS)で見た目のワールド空間へ持ち上げてから**
  スタックを適用し、逆行列でメッシュ空間へ戻す。デフォーマのジョブが見る `MeshBuffers.Vertices` は
  常にワールド空間(バインドポーズから個別調整されたボーンでも見た目と一致)
- 参照する体も**同じ LBS(ボーン × バインドポーズ)**でワールド空間へ持ち上げる。
  このため `VertexSkinning` を Editor アセンブリから Runtime(`Runtime/Data/VertexSkinning.cs`)へ移し、
  デフォーマ側からも使えるようにした(Editor 側のベイクコア・プレビューキャッシュはそのまま参照)
- `PrepareBake(Mesh)` はベイク 1 回につき 1 度、`Schedule` より前にメインスレッドで呼ばれる。
  **PrepareBake 直後の最初の Schedule は基本形状のパス**であり、以降はブレンドシェイプフレーム
  (`Deform(base + delta) − Deform(base)`)のパス(この契約を `DeformerBase` の doc に明記)
- プレビューのホットパス(約 20Hz)も `PrepareBake → Schedule` 1 回で、頂点だけを更新する。
  `Normals` / `Tangents` を要求するとホットパスが無効になるため、Body Fit は `Vertices` のみ要求する

## 3. 二重球の意味と「ぴったり / ブカッと」

### 3.1 検討した解釈

| 案 | 内容 | 評価 |
|---|---|---|
| A. ゲージ | 内球 = 体、外球 = 衣装の代理。球の隙間そのものを「体との隙間」とみなし、外球を内球に近づけると衣装が締まる | 隙間はミリ単位で、球のハンドルとして扱える大きさではない(半径 0.5 m の球に 5 mm の差を付けても見えない)。体は球ではないので隙間の定義も曖昧。**不採用** |
| B. 適用範囲 | 内球 = 100% 適用、外球 = 減衰の外縁。球を広げれば衣装全体、狭めれば胸・腰など部分的に | Sphere Mask / Cylindrical 系と同じ操作感で、既存の `RadiusSlider(pairProperty)` + `Circle` ハンドルがそのまま使える。「近づけたり遠ざけたり」は帯の幅(減衰の急さ)として自然に対応する。**採用** |
| C. 放射スケール | 球中心へ向かって半径方向に縮める(Cylindrical Scale の 3D 版) | 体のメッシュを見ないため体に沿わない。既存の Cylindrical Scale + Sphere Mask で代替可能。**不採用** |

「体に近づける / 遠ざける」量は球ではなく**数値(m)** で持つ。体は球ではないので、
体との距離は**体表面の最近接点からの法線方向距離**として測るのが唯一整合する定義であり、
この量は球の半径差とは無関係だからである。

### 3.3 レシピ

| 目的 | 設定 |
|---|---|
| ぴったり(ボディスーツ・タイツ。元の隙間が 1 cm 以内の服) | `minGap = maxGap = 0.002〜0.005`, `factor = 1`, 平滑化 2〜4。元の隙間が大きい服を潰してでも寄せるなら `maxShrink = 0`(面の潰れ・輪郭の縮みは §13.7) |
| 通常の服(シャツ・ワンピース)= 既定 | `minGap = 0.005`, `maxGap = 0.02`(帯の中は動かさない), `maxShrink = 0.15`, `factor = 1` |
| ブカッと(パーカー・オーバーサイズ) | `pullIn = false`, `minGap = 0.008`(めり込みだけ直す)。または `maxGap = 0.05` と `factor = 0.5` で「寄せつつドレープを残す」 |
| 部位で範囲を絞る(胴だけ・袖だけ・靴は足を外す・裾を自由にする) | `region = Parts`、`regionParts` で部位を選ぶ(§15)。縫い目は所属の混合で自動的になだらか |
| 部分的な修正(鎖骨の浮きなど) | 小さな二重球(`region = Sphere`)をもう 1 つ追加して局所適用。同じ体を参照する Body Fit はフィットグループで平均される(§14) |
| 範囲を絞る(部位より細かい) | Body Fit の後段に UV Island Mask / Vertex Color Mask / Box Mask を重ねる(マスクは前段の変形を打ち消す) |
| 重ね着 | 下着 → 服 → コートの順に、各 Body Fit の `body` を 1 つ内側の衣装のレンダラーにする。ベイク順は自動 |

## 4. 幾何コア

### 4.1 参照表面(`ReferenceSurfaceUtility` / `ReferenceSurfaceCache`)

1. 参照レンダラーのメッシュを解決する。Editor 側フック `DeformedMeshResolver` が
   「参照先に Deform Stack があればその変形後メッシュ」を返す(§8.3)
2. `useBodyBlendShapes` なら SMR の現在の重みを区分線形補間で頂点に適用する
   (最終フレームを超える重みは最終フレームで頭打ち)
3. SMR は `VertexSkinning`(頂点ごとの LBS)でワールド空間へ。MeshFilter は `localToWorldMatrix`
4. 写像が鏡映(行列式が負)なら三角形の巻き順を戻す(法線が内向きになるのを防ぐ)
5. `MeshSurface.Build` で BVH と擬似法線を構築し、レンダラー × シェイプ適用 × 反転 をキーに
   キャッシュする。ハッシュ(メッシュ ID・頂点数・変形後バージョン・全ボーンの行列・
   シェイプ重み・Transform)が変わらない限り再構築しない。同じ体を参照する複数の Body Fit で共有される
6. **複数レンダラー**(`additionalBodies`): 体が Body / Body2 のように分かれているアバターでは、各レンダラーの
   頂点・三角形・パーツマスクを 1〜4 の手順で作ってから連結し、BVH・擬似法線・半径プロファイルは結合後に
   構築する(`ReferenceSurfaceCache.TryGet(IReadOnlyList<Renderer>, …)`)。キャッシュは主レンダラー + 結合フラグ
   で持ち、ハッシュは各レンダラーのハッシュの組。レンダラーの境界(首の付け根など)では擬似法線が片側だけに
   なるが、衣装が接する部位では実用上問題にならない(§5 e と同じ)

### 4.2 最近接点クエリ(`MeshSurface` / `MeshSurfaceData`)

- **BVH**: 重心の最長軸を中央値分割、葉 ≤ 4 三角形、ノードは深さ優先順で配列化し
  **スキップポインタ**(部分木を飛ばした次のノード)を持つ。走査は `while (i < n)` の
  1 ループでスタック不要。`com.unity.collections` も `unsafe` も使わない
  (Runtime は Burst + Mathematics のみ依存という制約に合う)
- **最近接点**: Ericson (Real-Time Collision Detection 5.1.5) の重心座標法。
  最近接点が面 / 辺 / 頂点のどれに載るか(特徴)を同時に返す
- **内外判定**: 角度重み付き擬似法線(Baerentzen & Aanaes, 2005)。
  面 → 面法線、辺 → 隣接 2 面の法線和、頂点 → 角度重み付き法線和。
  頂点は位置で溶接して集計するため、UV シームで分割された頂点でも法線が途切れない
- 符号付き距離 `d = |p − q| · sign(dot(p − q, n))`(外側が正)
- メモリ(体 20 万三角形): 頂点 + 三角形 + 面法線 + 辺法線(3/三角形)+ 頂点法線(3/三角形)+
  ノード ≈ 25 MB。エディタ常駐、ビルド成果物には含まれない
- 構築はメインスレッドの managed コード(20 万三角形で数百 ms、体の姿勢が変わった時のみ)

### 4.3 ジョブチェーン(`BodyFitDeformer.Schedule`)

```
QueryJob        頂点ごと: 領域重み w、最近接点、目標 t = clamp(d, minGap, maxGap)
                 delta = (q + u·t) − p   (u = 外向き単位ベクトル)、valid = 対象かどうか
SmoothJob × k   有効な隣接の平均へ strength だけ寄せる(ピンポンバッファ)
ApplyJob        p += delta·w·factor、displacement = delta·w を記録
EnforceMinGapJob(平滑化時のみ) 再クエリして d < minGap の頂点を押し出す
```

- 外向き単位ベクトル `u` は、頂点が表面から離れていれば `(p − q)/|p − q|` を符号で外向きに揃えたもの、
  表面上なら擬似法線。辺・頂点特徴でも「表面から離れる方向」が正しく出る
- 平滑化は**位置ではなく変位ベクトル**に掛ける。位置を平滑化すると衣装自体のディテール
  (ボタン・折り目)が溶ける。対象外(領域外・探索圏外)の頂点は平均に含めず、動かさない
- 隣接(`MeshAdjacency`)は位置で溶接した CSR。同一位置の頂点は同じ隣接集合を共有するため、
  シームで裂けない。隣接リストは代表頂点を指す
- 一時配列は `Allocator.TempJob` で `Dispose(JobHandle)` を連鎖。常駐配列(参照表面・隣接・基本変位)は
  `Persistent` で、`OnDisable` / `OnDestroy` / ドメインリロード前 / エディタ終了時に回収する
- 計算量: 頂点 7 万 × BVH クエリ(数十〜数百ノード)。領域外の頂点はクエリしないため、
  球を絞れば比例して軽くなる

### 4.5 パーツ円柱モード(`FitMode.PartCylinder`、既定)

最近接写像は「距離しか見ない」ため、腕の紐飾りが胴に吸われる・立体的な装飾が隙間の距離まで
押し潰される・脇や股で隣のパーツへ写る、という失敗が構造的に避けられない。
そこで、体と衣装の**パーツ構造**を把握し、パーツごとの**ボーン軸を基準に放射状へ**動かす。

#### 4.5.1 パーツ把握(`BodyParts.cs` / `PartLabeling.cs` / `BoneNameMatcher.cs`)

- パーツ: ヒューマノイド骨格を 17 種に集約(Torso = Hips/Spine/Chest/UpperChest、Neck、Head、
  左右の Shoulder / UpperArm / LowerArm / Hand(指を含む)、左右の UpperLeg / LowerLeg / Foot(つま先を含む))。
  32 ビットのマスクに収まる数に抑え、三角形のパーツマスクと検索の絞り込みに使う
- 骨格(`HumanoidSkeleton`): **体側**の `Animator`(ヒューマノイド)から作る(体に無ければ衣装の親の Animator)。
  各パーツの円柱軸はボーン区間(UpperArm → LowerArm など。胴は Hips → Neck、頭・手・足は骨の方向へ延長)。
  θ = 0 の基準方向は軸から決定的に決める。衣装のボーン位置が軸になることは無いので、
  体と衣装でボーン位置が違っても幾何的なズレは生じない。任意ボーン(Shoulder / Neck / UpperChest)の
  有無はアバターごとに違うため、軸の無いパーツは近いパーツへ丸める(`Canonical`: Shoulder → UpperArm、
  Neck → Torso)。ポーズ変更は `Refresh` でボーン位置だけ読み直して追従する

**衣装の頂点がどのパーツに属するか**は、以下の 2 種類の証拠を UV 島(または 3D 連結成分)単位で投票して決める
(`PartLabeler`)。最近接近似の失敗(腕の紐飾りが胴に吸われる、脇・股で隣のパーツへ写る)は
「距離しか見ない」ことが原因なので、位置以外の情報を主にする。

1. **ボーンウェイト**(作者の意図そのもの)。衣装ボーン → パーツの対応付け(`MapBones`)は位置に頼る段を最後に回す:
   1. ヒューマノイドボーンとその子孫(体の Animator、または衣装自身のヒューマノイド Animator。
      マージ済み衣装・胸や尻尾などの補助ボーン)… 信頼度 1
   2. ボーン名(`BoneNameMatcher`: UpperArm_L / J_Bip_L_UpperArm / upper_arm.L / 左腕 / mixamorig:LeftForeArm …。
      左右が判別できない四肢名やスカート・リボンなど装飾語を含む名前は「不明」)… 信頼度 1
   3. 衣装アーマチュア内で対応済みの祖先(スカート・リボンの補助ボーン → Hips や腕へ)… 親の信頼度
   4. 関節位置の一致(許容 `jointTolerance`)… 信頼度 0.5(体と衣装の骨格の比率が違うと外れる)
   5. 最寄りの軸区間 … 信頼度 0.25
   頂点のパーツ重み(`FromBoneWeights`)はウェイトをパーツごとに合算した上位 4 つ。関節付近の混合ウェイトは
   そのまま複数パーツへの所属になり、放射変位を重み付きで混ぜることで関節で滑らかにつながる。
   対応付けの信頼度もウェイトで平均して頂点ごとに持つ
2. **体の形状**(`PartGeometryJob`)。頂点を各パーツの軸で円柱座標に分解し、そのパーツの半径プロファイル
   R(h, θ) からの隙間 r − R を比べる(h が軸区間から 15% 以上外れるパーツは除外、体の内側は半分の重さ)。
   隙間が最小のパーツを 1、2 番目は差が小さいほど重みを持つ(脇では腕と胴の両方が候補になる)。
   ウェイトの無い衣装(MeshRenderer・小物)でも使え、対応付けの誤りを検出できる。
   ただし装飾が隣のパーツに近い場合は間違えるので**単独では使わない**

頂点ごとの所属 = 信頼度 c でウェイトを、(1 − c) で形状を混ぜたもの。名前やヒューマノイドで対応付いた
衣装ではウェイトがそのまま採用され、位置頼みの対応付けほど形状の意見が強くなる。

**投票と統一**(`PartLabeler.Label`): グループ = UV 島(`partGrouping = UVIslands`、UV が無ければ連結成分)。
グループごとに頂点の所属を合算し、

- バウンズ対角が `decorationMaxSize` 以下(紐・リボン・ボタン)→ 比率に関わらず上位 1 パーツに揃える
- 上位の比率が `islandConfidence` 以上(袖・身頃・スカート)→ 1 パーツに揃える
- 届かない(ボディスーツ・ロングコートなど複数パーツにまたがる 1 島)→ 頂点ごとの所属のまま
- 手動上書き(`partOverrides`)があればそれ

ウェイトの上位と形状の上位が食い違う(両方 60% 以上)グループ、および大きいのに頂点ごとに落ちたグループは
**要確認**としてインスペクタに列挙し、グループ単位でパーツを指定できる(§9)。どんな自動判定でも外れる衣装は
あるので、ここが実用上の要。上書きは UV 島の代表 UV(`IslandSeed`)/ 連結成分の代表点で保存し、
頂点順が変わっても追従する。

**縫い目**(`BlendSeams`): 島単位で揃えると袖付けの縫い目がハードな境界になり、袖は腕軸・身頃は胴軸で
動いて裂ける。そこで同位置の頂点(UV シームで分割された頂点)の所属を平均して裂けを防ぎ、
所属の異なる頂点に接する頂点を `seamBlend` 回だけ隣接平均へ寄せて遷移を広げる。

**軸区間の外**(`ApplyAxisRangeFallback`): 腰より下に垂れる裾(トップスの裾・ワンピースのスカート)は
Hips のウェイトしか持たないため胴に揃うが、胴の軸(Hips → Neck)から見ると h < −0.25 と半径プロファイルの
範囲外で、端(骨盤)の値でクランプして評価すると股の前の布が骨盤の半径へ引き込まれる。裾の高さで実際に
近いのは太ももなので、投票・統一・上書きの結果に関わらず、**支配パーツの h がプロファイルの範囲
[−0.25, 1.25] の外にある頂点は形状証拠(最寄りのパーツ)へ差し替える**(形状の候補が無い頂点はそのまま)。
差し替えた頂点数はグループの判定(`PartGroupReport.OutOfRangeCount`)に載せ、インスペクタに
「軸区間外の N 頂点は形状で判定」と示す。`partSource = BoneWeights` では形状証拠が無いので差し替えない。

`partSource` で証拠を限定できる: BoneWeights(ウェイトのみ。従来どおり)/ Geometry(形状のみ。ウェイトが
壊れている・無い衣装向け)。

#### 4.5.2 体の半径プロファイル(`PartProfileData`)

パーツ p の軸上の点から、周角 θ の方向へ**そのパーツの三角形だけ**を対象にレイを飛ばし
(パーツマスク付きレイキャスト)、最初の交点までの距離を R_p(h, θ) として 32 × 32 の格子に持つ。
h は軸区間 [0, 1] を少し超えて [−0.25, 1.25] を覆う。レイが当たらない格子は近傍平均で埋める
(体メッシュの上端より上の襟など体の無い行も端の行の値で外挿する。そこの布を「参照なし」として
動かさないと、体のある行の布だけが動いて裂けるため。§13.5)。ヒットがほとんど無いパーツは使わない
(そのパーツの頂点は動かさない)。放射変位場の双線形サンプルは NaN の角を除いて重みを正規化する
(`SampleGridSkipNaN`)。
プロファイルは参照表面キャッシュに同居し、体・骨格が変わらない限り再構築しない。

#### 4.5.3 衣装の放射変位場(`RadialFieldJob`)

1. 各衣装頂点を、所属する各パーツの軸で円柱座標 (h, θ, r) に分解する(`CylinderCoordJob`)
2. 支配パーツ(重み 0.5 以上)の格子ごとに**最内層の半径** r_min(h, θ) を取る(体に触れる層)。二重球の
   領域の重みに関わらず全頂点から取る(領域は変位の適用にだけ効く。§14.1)
3. Δr(h, θ) = clamp(r_min, R + minGap, R + maxGap) − r_min。値の無い格子は近傍から 2 周だけ埋め、
   `smoothIterations` 回の 3 × 3 平滑化で滑らかにする(θ 方向は周期)
4. 各頂点は所属スロットごとに Δr を双線形サンプルし、**放射方向**に重み付きで合成して動かす
   (`RadialApplyJob`)。同じ格子の頂点は同じ Δr で動くので、装飾は下地との相対オフセットを保つ
5. 最後にパーツ制限付きの最近接点で minGap を再保証する(`EnforceMinGapJob`)。ただしパーツの三角形集合は
   閉じていない(骨盤と太ももの境界の面など)ため、パーツの外側にある頂点でも境界面の裏側にあれば
   「内側」と判定され、面の向こうへ大きく押し込まれる(裾が股へ押し込まれる)。そこで押し出しが要ると
   判定した頂点だけ**全身の最近接点も引き**、必要な補正量(minGap − d)が小さい方を採用する
   (`ResolvePushOut`)。全身で見て隙間が足りていれば押し出さず、本当にめり込んでいる頂点は最も近い
   壁から外へ出す。逆に、自分のパーツの三角形が遠くて「十分外側」に見える頂点(襟元と肩マスクなど)でも、
   全身で見て体の内側なら押し出す(パーツ制限は引き寄せ先の選択のためで、めり込みを許す意図ではない)。
   最近接表面モードのパーツ制限付き検索(`QueryJob`)の押し出しも前者と同じ規則

この方式で「装飾が潰れる」「腕の紐が胴に付く」「脇・股で別パーツへ写る」が構造的に解消される。
関節では複数パーツの放射変位が重みで混ざる。ヒューマノイドの Animator が無いプロジェクト
(小物・ワールド用途)では自動で最近接表面モードへ切り替わる。

#### 4.5.4 肩まわり(袖付けの縫い目)の反転への対策(実験的オプション)

胴の軸は Hips → Neck の直線なので、肩の上面では胴軸からの放射方向がほぼ水平になり、表面法線(上向き)と
食い違う。HAOLAN のアウターでは肩の上面の胴所属 1,478 頂点が脊椎側へ水平に中央値 23.5 mm 引き寄せられ
(上下は 1 mm 未満)、袖(上腕軸の放射)との縫い目で 1 mm 幅の細い三角形が反転する(反転面 135 のうち 126 が
胴と上腕の所属が混ざる頂点を含む)。次の 3 案をオプションとして実装し、§13.4 で比較した。

1. **縫い目の変位平滑化**(`seamSmoothIterations` / `seamSmoothAll`): 放射変位を求めた後、所属が混ざる頂点と
   隣に支配パーツの違う頂点がある頂点(`SeamMaskJob`)だけ、変位ベクトルを頂点隣接の平均へ `smoothStrength`
   だけ寄せる(`MaskedSmoothJob`、ピンポン)。`seamSmoothAll` で全頂点
2. **肩甲帯**(`shoulderAxis` / `shoulderCapMargin`): 肩の軸を「脊椎(胴の軸)上の肩の高さの点 → 上腕関節」
   にする(`HumanoidSkeleton.ShoulderFromSpine`。Shoulder ボーンが無くても作る)。肩のプロファイルのレイは
   胴・上腕の三角形にも当てる(肩は胴と腕の橋なので)。胴の軸で上腕関節の高さ − margin より上にある頂点は、
   所属の胴成分を左右の肩へ置き換える(`ApplyShoulderCap`。袖との混合は残す)。肩の軸から見ると上面は上向き、
   胸・背は前後向き、脇の下は下向きに放射し、上腕の軸とほぼ同一直線なので袖付けで放射方向が連続になる
3. **関節の扇状放射**(`jointFan`、折れ線軸の近似): 所属が混ざる頂点は、所属パーツの軸(線分)の最寄り点から
   放射し、大きさは所属ごとの Δr の重み付き和にする。関節の外側(肩の上)では放射方向が扇状につながるが、
   内側(脇の下)では最寄りの線分が切り替わる境界で方向が不連続になる(折れ線・スプライン軸そのものを
   持っても凹側のこの性質は同じ)

#### 4.5.5 装飾の追従(`rigidDecorations`)と縮み率の上限(`maxShrink`)

輪郭の歪み(§13.7)への対策。襟・紐・ボタンのような小さなグループは、頂点ごとに放射させると
(1) 張り出した先端がその格子の最内層として体の半径 + 隙間まで潰れる、(2) 首・頭のように傾いた軸の
放射では上下成分が乗って部品が傾く、(3) 部品の中で所属(軸)が切り替わると向きが変わる、の 3 つで
輪郭が崩れる。そこで `rigidMaxSize`(既定 0.2 m)以下のグループは**付け根の頂点の変位を写す**
(`BuildFollowSources` / `FollowJob`): 付け根 = 他のグループの頂点と同じ位置にある(UV シーム)/
隣接している / 1 cm 以内にある頂点で、グループの各頂点は最も近い付け根の変位をそのまま使う。
付け根の無いグループ(どこにも付いていない)と大きなグループは頂点ごとの放射のまま。
装飾が体に触れる場合のめり込みは minGap の再保証が個別に押し出す。

`maxShrink` は放射変位場の段階で Δr ≥ −maxShrink × r_min と下限を付け、周を一定率より縮めない。
元の隙間が大きい服をぴったり設定で寄せるときの面の潰れ(面積比 0.4 級)を抑える代わりに、
その分の隙間が残る。

## 5. メッシュの交差

| ケース | 扱い |
|---|---|
| (a) 衣装の頂点が体の内側 | 符号付き距離が負 → `minGap` まで外へ押し出される(専用処理なし・同じ式) |
| (b) 頂点は外側だが三角形が体を横切る | 頂点変位のみの設計では保証できない。`minGap > 0` と平滑化で緩和。衣装の分割数を上げるか、その部分をマスクで除外する。三角形単位の衝突補正は将来候補 |
| (c) 衣装の自己交差(スカートが脚に貼り付いて重なる等) | 非目標(布シミュレーション級の問題)。`factor` を下げる・`maxGap` を広げる・`pullIn` を切る・マスクで除外 |
| (d) 反対側への写像(薄い部位で裏側の面が最近接になる) | `searchDistance` で上限を切る。深くめり込んだ頂点ほど危険なので、局所の Body Fit を小さな球で複数置く運用を推奨。衣装法線との整合(法線が逆向きの候補を捨てる)は、法線チャンネルを要求するとホットパスが無効になるため v1 では見送り |
| (e) 体が閉じていない(首・手首の開口) | 境界辺の擬似法線は片面のみ。開口の縁付近で符号が不安定になり得るが、衣装が接する部位では実用上問題にならない |
| (g) 二重構造の薄い衣装(表地と裏地、スカートの内外) | パーツ円柱モードでは格子の最内層だけが隙間の基準になり、他の層は同じ Δr で動くので厚みは保たれる。最近接表面モードでは両方の層が同じ隙間へ寄るため、`pullIn` を切るか `maxGap` を層の厚み以上に広げるか、裏地を UV Island Mask で除外する |
| (f) 別の部位への橋渡し(脇の下で袖口の頂点が胴体を最近接にする等) | パーツ円柱モードでは腕の頂点は腕の軸基準でしか動かず、最近接表面モードでもパーツ制限で自分のパーツの三角形だけを探すため、構造的に起きない。骨格が無い(パーツ不明)場合のみ、二重球を分けて置く・`searchDistance` を絞る・袖を UV Island Mask で除外する、で回避する |
| (h) パーツ境界の面による「内側」の誤判定(胴所属の裾が、胴パーツに含まれる太ももの内側の壁の裏にある等) | パーツの三角形集合は閉じていないため、パーツ制限付きの最近接だけでは起きる。押し出し時に全身の最近接点も見て補正量の小さい方を採る(§4.5.3 の 5)。加えて軸区間の外の頂点は形状で最寄りのパーツへ移す(§4.5.1)ので、裾は太ももの三角形を探すようになる |

## 6. ウェイト

### 6.1 適用範囲の重み(変形の重み)

- 二重球を内蔵する理由: (1) ユーザーの操作モデルに一致する、(2) 領域外の頂点はクエリ自体を
  省けるので性能に直結する
- それ以上に細かい範囲指定(袖だけ除外、裾は自由)は**既存のマスクを後段に重ねる**。
  マスクはそのパスの入力スナップショット(`OriginalVertices`)へ戻す仕様なので、
  Body Fit の後に UV Island Mask を置けば「その島は元の形のまま」になる。
  → 「別 Deformer に役割を分けるか」への回答: 範囲の重みについては**既存デフォーマで分担済み**、新規不要

### 6.2 ボーンウェイトの転写(別機能として切り出す)

体に沿わせても衣装のボーンウェイトは元のままなので、動かしたときの追従は衣装の元ウェイト次第になる。
体のウェイトを衣装へ転写する機能は**Body Fit とは分離**する(要望どおり)。理由と、実装する場合の設計メモ:

- 現状 `MeshBuffers` にボーンウェイトのチャンネルが無く、ベイクコアは「ボーンウェイト・バインドポーズは
  素通し」を契約にしている(README の既知の制限)
- 必要になる拡張:
  1. `DeformDataFlags.BoneWeights` と `MeshBuffers.BoneWeights`(`BoneWeight1` + 頂点ごとの本数、可変長)
  2. 衣装 SMR の `bones` と体 SMR の `bones` の対応付け(Modular Avatar のマージ後は同一 Transform、
     マージ前は名前・パスによる対応)と、衣装側に無いボーンの追加(`bones` / `bindposes` の拡張)
  3. 転写元の対応点: Body Fit と同じ最近接点クエリ(`MeshSurface`)で三角形と重心座標を取り、
     体の 3 頂点のウェイトを重心補間する(再利用可能)
  4. NDMF の他プラグイン(Modular Avatar の Merge Armature 等)との順序保証
- 「Weight Transfer」デフォーマ(Utility カテゴリ)として、Body Fit と同じ `IRendererReferences` を実装し、
  同じ参照表面キャッシュを使う想定。ロードマップ候補 M10 として rearchitecture.md に追記

## 7. ブレンドシェイプ

ベイクコアは各シェイプフレームを `Deform(base + delta) − Deform(base)` で作り直す。
体へ再フィットする変形をそのまま通すと、衣装の「胸を大きくする」シェイプは体の基本形状へ潰され、
体側の同名シェイプを動かした時に衣装が追従しなくなる。

| モード | 動作 | 用途 |
|---|---|---|
| `FixedDisplacement`(既定) | 基本形状パスで求めた変位(重み込み)を保存し、シェイプフレームのパスではそれを足すだけ。`Deform(x) = x + D` は線形なので**衣装のシェイプデルタは完全に維持**され、中間フレームも増えない。シェイプ数 × BVH クエリが不要でベイクが軽い | 通常はこれ |
| `RefitEachFrame` | フレームごとに再クエリして体へフィットする(シェイプ後の形状も体に沿う) | 別素体向けのシェイプを無効化したい特殊用途 |

既存の `KeepAuthoredShape`(スタック側のシェイプ別設定)では不十分な理由: これは「シェイプ 100% で
作者の形状(`base + delta`)そのもの」へ戻すため、そのシェイプが動かす頂点では**フィット自体が消える**。
FixedDisplacement は「フィット後の形 + 作者のデルタ」になる点が異なる。

体側のブレンドシェイプ: `useBodyBlendShapes` でレンダラーの現在の重みを反映する(表示どおりの体に
フィット)。ベイクは静的なので、ランタイムで体のシェイプが動いても衣装は追従しない
(衣装側に対応するシェイプがあれば FixedDisplacement で維持されるので、体と同期して動かせる)。

## 8. 統合

### 8.1 参照の宣言(`IRendererReferences`)

他のレンダラーを入力に使うデフォーマは `CollectReferencedRenderers(List<Renderer>)` を実装する。
Body Fit 固有の分岐をプレビュー・ベイクパスに持ち込まないための小さな契約。

### 8.2 プレビューの監視(`DeformStackPreview`)

参照レンダラー・その Transform・(あれば)参照先の Deform Stack とそのデフォーマ・軸を
`ComputeContext.Observe` に加える。ボーンの移動は(衣装自身のスキンと同様に)監視しない。
このため体をポーズ付けしてもプレビューは再ベイクされず、参照表面(BVH)の再構築も起きない
(次にデフォーマや軸を触った時点で新しい姿勢で作り直される。ビルドは常に 1 回構築)。

### 8.3 重ね着: ベイク順序と変形後メッシュの解決

- **ビルド**(`BakeDeformStacksPass`): `DeformStackOrdering.Sort` で参照先が先になるよう
  安定な Kahn 法で並べ替える(循環は警告して入力順)。各スタックはベイク直後にコンポーネントを破棄する。
  これにより、後続の Body Fit が参照先を見た時には `sharedMesh` がベイク済みメッシュで、
  Deform Stack はもう無い(= フックが二重に変形しない)
- **プレビュー**(`DeformedReferenceResolver`, Editor): 参照先に有効な Deform Stack があれば
  `DeformPreviewBakeCache.Bake` を参照先自身のプレビューと同じ引数で呼び、そのベイク済みメッシュを返す。
  同じキャッシュエントリに乗るためホットパスで安い。再入ガードで循環を打ち切る。
  返すメッシュはインスタンスが同じまま中身が更新される(ホットパス)ため、
  `BakeSerial` をバージョンとして返し参照表面キャッシュのハッシュに含める

### 8.4 キャッシュと寿命

| データ | 所有 | 無効化 |
|---|---|---|
| 参照表面(BVH・法線) | `ReferenceSurfaceCache`(静的、レンダラー × 設定) | ハッシュ不一致 / レンダラー破棄 / ドメインリロード |
| 衣装隣接(CSR) | デフォーマインスタンス | ソースメッシュ・頂点数の変化 |
| 基本変位 | デフォーマインスタンス | PrepareBake ごとに上書き |

## 11. 既知の制限とロードマップ

- 三角形単位の交差・衣装の自己交差は保証しない(§5)
- **最近接表面モードでぴっちり(minGap = maxGap = 3 mm)にすると布が折れる・層が潰れる**(§13.3)。
  最近接点写像は各頂点を独立に体表面へ写すため、表地と裏地・紐と身頃のような重なった層が同じ隙間へ
  寄って互いを貫き(§5 g)、脇・股の凹みでは隣の頂点が離れた面へ写って折れる(§5 c)。HAOLAN の
  トップスでは自己交差が 820 → 6,876、アウターでは 15,748 → 30,475 になり、平滑化を 20 回・強さ 0.8 まで
  上げても 5,224 / 28,886 までしか減らず、反転面も 300 / 700 前後のまま(minGap の再保証を切ると交差は
  減るが体の内側に頂点が残る)。変位の上限や平滑化の強化では緩和できないので既知の制限とする。
  ぴっちりした服にはパーツ円柱モード(ヒューマノイドなら既定)を使う。骨格が無く最近接表面しか
  使えない場合は、帯を広げる(`maxGap` を層の厚み以上)か `pullIn` を切り、裏地・紐は UV Island Mask で除外する
- 反対側への写像は `searchDistance` と局所適用で回避する運用(§5 d)
- 首から上が別レンダラーのアバター(HAOLAN の Body / Body2)では、`additionalBodies` に首から上のレンダラーを
  入れないと襟が首を参照できず、肩の布と同じ量だけ動く(§13.5)。自動検出は名前に body を含むレンダラーを
  追加するが、Head / Face のような名前は手動で入れる(§13.6)
- 体のブレンドシェイプのランタイム変化には追従しない(静的ベイク)
- ボーンウェイトは変更しない → **M10 候補: Weight Transfer デフォーマ**(§6.2)
- パーツ円柱の軸は直線のボーン区間なので、胴の肩まわり・股の付け根のように軸から見た放射方向が
  表面法線と大きくずれる部位では、隙間の実測値が法線方向の距離より大きめに出る(`minGap` の再保証で
  めり込みは防ぐ)。HAOLAN のアウターでは肩の上面の布が脊椎側へ水平に約 2 cm 滑り、袖付けの細い三角形が
  約 130 面反転する。縫い目の変位平滑化・肩甲帯(脊椎 → 上腕関節の肩軸)・関節の扇状放射の 3 案を
  実験的オプションとして実装し比較したが(§4.5.4 / §13.4)、肩甲帯で反転面 134 → 100・滑り半減が最良で、
  無くすには至らない。根本対策は肩まわりを 1 本の連続した軸(折れ線 / スプライン)と 1 枚のプロファイルで
  扱うことで、将来候補のまま
- パーツ所属の自動判定は投票(§4.5.1)だが、ウェイトが崩れていて形状も曖昧な装飾(脇の下の飾りなど)は
  外れうる。要確認の一覧と手動上書きで補う運用。UV 島が細かすぎるメッシュ(ボタンごと)は
  `decorationMaxSize` で揃い、1 島の全身スーツは頂点ごとの所属になる
- 軸区間の外(h < −0.25 / h > 1.25)の頂点は形状で最寄りのパーツへ移す(§4.5.1)。どのパーツの軸区間にも
  入らない頂点(足より下に垂れるロングスカートの裾など)は所属パーツのプロファイルの端の値で評価される。
  裾を自由にしたい場合は `pullIn` を切るか、`region = Parts` で脚を外す(§15)。全身テスト(§13.8)では
  太ももまで垂れる inner の裾が脚のプロファイルへ 10〜16 mm 引き寄せられ、辺の伸縮率 p90 が 20〜29% になる
- 重ね着の各衣装は体だけを見て独立に合わせるため、下の服(HAOLAN の pants は buggypants の内側で体に 33 mm
  めり込んでいる)を押し出すと上の服を突き抜ける(§13.8)。隠れる服は Body Fit を付けない、または `body` を
  1 つ内側の衣装にする(§3.3 重ね着)
- 靴のような厚みのある硬い装具(HAOLAN の sneakers: 靴底・舌・紐の層が数 mm 間隔で重なる)を足の
  プロファイルへ寄せると層が互いに貫き反転面が出る(§13.8。既定で 128 面)。靴は `region = Parts` で足を
  外すか Body Fit を付けない
- 将来候補: 衣装法線に沿ったレイ投影モード、三角形衝突補正パス、Burst での BVH 構築、
  頂点ペイントによる隙間の局所指定(Vertex Color を隙間のスケールに使う)、
  シーンビューでのグループ選択(UV Island Mask の選択 UI の流用)

## 14. 複数の Body Fit を重ねるときの設計(検討)

### 14.1 現在の挙動

Deform Stack は各デフォーマを順に適用し、後段は前段の結果を入力にする。Body Fit を複数置くと
(胸・腰・腕などに二重球を分けて置く、参照する体が違う重ね着など)、次の性質になる。

- **残差の逐次適用**: 各 Body Fit は「今の位置」から体までの隙間を測って目標へ動かすので、重なりでは
  2 つ目が残りの差を詰める。重み w₁, w₂ の合成は 1 − (1 − w₁)(1 − w₂)。目標(体の面 + 隙間)が同じなら
  行き過ぎない
- **後段優先**: 設定(隙間・モード)が違えば重なりでは後段の目標に近づく。順序に依存する
- **上限の累積**: `maxShrink`(縮み率の上限)と `factor` は Body Fit ごとに掛かるので、重なりでは
  15% + 15% のように累積する。単独では止まる寄せが重なりでは進む
- **隙間(中間点)**: どの球にも入らない頂点は動かない。減衰帯(内半径〜外半径)が届く所は部分的に動く。
  球の外半径が中間点で接するだけの置き方だと、中間点の重みは 0 に近く、両側だけが寄って段差になる
- **格子の最内層**: 放射変位場 Δr の最内層 r_min はメッシュ全体から取るように改めた(§4.5.3)。以前は
  領域内の頂点だけから取っていたため、最内層が球の外にあると球内の外側の層が最内層扱いで潰れていた。
  領域の重みは変位の適用にだけ効く
- **キャッシュ**: 参照表面(BVH・プロファイル)は体ごとに共有される。衣装のパーツ所属は Body Fit ごとに
  計算・保持する(同じ衣装 × 同じ骨格でも重複)

### 14.3 フィットグループ(同じ体を参照する連続した Body Fit の合成。実装済み)

逐次適用の「上限の累積」と「後段優先」を無くすため、同じ体を参照して連続する Body Fit を
**1 つのグループ**として扱い、各メンバーの変位を**同じ入力(グループ直前の位置)から**求めて重みで合成する
(`fitGroup`、既定オン)。

- 各メンバー i は自分の領域重み wᵢ と目標変位 dᵢ(グループ入力から。上限・factor 込み)を求める
- 合成: p' = p + Σ wᵢ dᵢ / max(1, Σ wᵢ)。Σ wᵢ ≤ 1 の所(単独・隙間)は今と同じ、Σ wᵢ > 1 の重なりでは
  重み付き平均になり、上限が累積せず、設定が違えば平均される(順序に依らない)
- 減衰帯を Σ wᵢ = 1 になるよう置けば中間点は 100% 動く(2 つの球の外半径が中間点で w = 0.5 になる置き方)。
  インスペクタで Σ wᵢ(カバー率)を頂点色で示すと置き方を確認できる
- 実装(`DetermineGroup` / `ScheduleGrouped`): 各メンバーが `PrepareBake` で親スタックの有効なデフォーマの
  並びを見てグループ(先頭・末尾)を決める。パスの最初に走ったメンバーが先頭の共有バッファ(入力のスナップ
  ショット、Σ w f d、Σ w。TempJob)を確保して入力を写し、各メンバーは自分のジョブチェーン(パーツ円柱 /
  最近接表面)をスナップショットに対して回し、`AccumulateJob` で累積へ足す。末尾メンバーが `CombineJob` で
  p' = snapshot + Σ w f d / max(1, Σ w) を書き戻し、minGap の再保証(重みは min(Σ w, 1)、末尾の設定)を
  1 回だけ行ってバッファを解放する。ブレンドシェイプの FixedDisplacement は末尾だけが合成済みの変位を足す。
  寄与できないメンバー(factor 0、表面なし)は累積へ足さないだけで、末尾の合成は必ず行う
- グループの境界 = 参照する体(`body` + `additionalBodies`)が変わる、間に他のデフォーマが挟まる、
  `fitGroup` が偽、のいずれか。方式(PartCylinder / NearestSurface)の違いは同じグループで混ぜられる。
  重ね着(体 → 下着 → 服)は体が違うので今までどおり逐次
- 計測(14.2 と同じ配置): 「接する」「重なる」「順序逆」の結果が全体 1 つと**完全に一致**(位置差 0.00 mm、
  反転面 14)。B をぴったりにした場合は重なり帯で両者の平均になり、反転面 1(逐次では 16)
- 単体テスト: factor 0.5 × 2 の重なりが平均(0.66)で累積しない(逐次なら 0.59)、maxGap 0.05 / 0.10 の
  順序を入れ替えても平均 0.575、参照する体が違えばグループにならず逐次(0.68)
- 未実装(将来候補): 衣装のパーツ所属のグループ共有(現状はメンバーごとに計算・保持)、
  インスペクタでのカバー率 Σ w の表示

### 14.4 運用

- 同じ服に複数置く場合はそのまま重ねてよい(フィットグループが平均する)。減衰帯が中間点で
  w = 0.5 ずつになるように球を置くと中間点も 100% 動く。減衰帯が届かない所は動かない
- 参照する体が違う Body Fit(重ね着)は今までどおり順に置く(逐次)
- 逐次の挙動(後段優先・残差の詰め)が欲しい場合は後段の `fitGroup` を切る

## 15. 二重球ハンドルの有用性の検討と、部位指定の適用範囲(Parts)

### 15.1 二重球で何が指定できているか

二重球(§3.1 案 B)は「衣装の中心からの距離」で効きを決める。衣装は体を包む筒なので、体の軸上に置いた球は
**高さの帯**を選ぶことになり、その帯の境界は球面なので前後・左右で高さが変わる。HAOLAN outerwear(胴の
軸 y 0.67〜0.98、布は軸から 0.10〜0.15 m)で測った性質:

| 置き方 | 動いた頂点 / 全体 | 反転 | 隙間 p90 (mm) | 所見 |
|---|---|---|---|---|
| WholeMesh | 15,363 / 18,241 | 14 | 35 | 基準 |
| 球 A(y 0.86、内 0.17 / 外 0.23) | 12,131 | 14 | 36 | 布に届くには半径 ≥ 0.15 m が要る(胴の軸から布まで 10〜15 cm)。減衰帯 6 cm が y 0.63〜0.69 と 1.03〜1.09 の「高さ帯」になる |
| 球 A + 球 B(y 0.70、接する) | 12,356 | 14 | 35 | 2 球の継ぎ目(減衰帯の重なり)は w = 0.5 + 0.5 でフィットグループが平均するので段差は出ない(§14.2) |
| 球 A + 球 B(重なる) | 13,143 | 14 | 35 | 同上。順序に依らない |
| `FitSphereToParentStack`(作成時の既定) | = WholeMesh | 14 | 35 | 内半径 = バウンズの半対角なので実質メッシュ全体。二重球の意味を持たない |

- 作成時の既定(衣装全体を覆う球)は WholeMesh と同じ結果になり、**二重球を触るのは「部分適用したい」ときだけ**
- そのとき選びたい単位は「袖だけ」「胴だけ」「裾は自由に」「靴は足を外す」のような**部位**であり、
  球で表すには (1) 中心を軸上に置く、(2) 半径を布まで届かせる、(3) 減衰帯が縫い目と一致しない
  (肩は球面で斜めに切れる)、(4) 左右の袖は 2 球要る、と手数が多く、境界はどうしても曖昧になる
- 局所の修正(鎖骨の浮き・脇の 1 か所)には球が向く。中心を当てる場所が「体の上の 1 点」で、半径を
  数 cm にすれば周囲だけ動く。この用途は残す

### 15.2 改善: 所属パーツで指定する(`FitRegion.Parts`。実装済み)

パーツ円柱モードは頂点ごとに所属パーツ(重み付き、最大 4 スロット。縫い目は `seamBlend` で混合、§4.5.1)を
持っている。これをそのまま適用範囲に使う。

- `region = Parts`、`regionParts`(`BodyPartMask`、`[Flags]`。ビット = 1 << BodyPart で `PartWeights.Mask` と同じ配置)
- 頂点の効き w = Σ(所属スロットのうち `regionParts` に含まれるパーツの重み)。所属が 1 パーツなら 0 か 1、
  縫い目では混合比のまま 0〜1 になるので**減衰帯を別に持たなくても境界がなだらか**。所属なし(None)は 0
- 最近接表面モードでも同じ重みで絞れる(所属はパーツ制限に使っているものを流用)。骨格が無く所属が
  取れない場合はメッシュ全体(`RegionMode` が WholeMesh へ落ちる)
- `regionFeather`: 領域の重みを頂点隣接で N 回ならす(`WeightSmoothJob`、w' = (w + 隣接平均) / 2 のピンポン)。
  境界が縫い目そのものになる Parts では、所属の混合幅(`seamBlend` 3 リング)だけでは片側が動き片側が
  動かない段差になり反転面が増える(§15.3)ので、境界を数リング広げる。パーツ円柱では放射変位が領域外の
  頂点にも計算されるので両側に効き、最近接表面では領域外の頂点は変位を持たないため内側の減衰だけが効く
- 二重球のハンドルは `region = Sphere` のときだけ描く。Parts のときはインスペクタのパーツ所属の要約に
  「全適用 / 縫い目で部分適用 / 対象外」の頂点数を添える(`TryGetRegionCoverage`)
- フィットグループ(§14.3)とは独立: Parts の Body Fit と Sphere の Body Fit を重ねても、それぞれの w で
  平均される

検討して見送ったもの:

| 案 | 内容 | 見送り理由 |
|---|---|---|
| 軸方向の帯(パーツごとの h 範囲) | 「胴の h 0.3〜1.0 だけ」のように軸上の区間で絞る | 裾(h < 0)は軸区間外で形状により脚へ所属が移るので、Parts で脚を外せば同じことができる。h の意味(0 = 根元、1 = 先端)がユーザーに見えず、区間の端に減衰幅の指定も要る |
| 頂点の可視化(w のヒートマップ) | シーンビューで対象頂点を塗る | 頂点数の要約で足りると判断。UV Island Mask の選択 UI と合わせて将来候補 |
| 二重球の廃止 | Parts に一本化 | 局所修正(§15.1)には球が向くので残す。作成時の既定は引き続き「衣装全体を覆う球」= WholeMesh 相当 |

### 15.4 運用

- 部位で絞るときは `region = Parts`。胴だけ(裾は自由)= Torso、袖だけ = 肩 + 上腕 + 前腕 + 手、靴 = All から足を外す。
  境界で反転・段差が見えたら `regionFeather` を上げる(既定 4、最大 10)
- 首から上・胴・脚のような「高さの帯」で切るなら `region = Sphere` の球でもよい(境界が布の途中に来るので段差が出にくい)
- 局所の修正は `region = Sphere` の小さな球(中心を体の上の 1 点に、半径 3〜8 cm)を追加で置く
- 作成時の既定(衣装全体を覆う球)は WholeMesh と同じなので、そのままでよければ触らない
